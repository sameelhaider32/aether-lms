# Aether LMS 1.3.1 stability audit

Audit date: 24 October 2026. Branch: `fix/v1.3.1-stability`.

## Baseline and scope

Fetched `main` from the public upstream and verified commit `1c204d3596b941344037ff06123d8b6d6a9a5ea3`. The requested Downloads checkout was clean on that commit. Work began in an isolated clone; main and contributor history were preserved. The final branch is intended to replace the existing Downloads checkout in place, without a second installation.

Reviewed merged PRs [#3](https://github.com/sameelhaider32/aether-lms/pull/3), [#2](https://github.com/sameelhaider32/aether-lms/pull/2) and [#1](https://github.com/sameelhaider32/aether-lms/pull/1), their merge commits and PR #3's 31-file change. Reviewed the manifest, package/lockfile, README, changelog, privacy/security/contribution/releasing guidance, earlier audit/release reports, CI/security workflows, all first-party JavaScript and the existing fixture/test architecture. No visual design or runtime dependency replacement was undertaken.

The existing infrastructure launches a real unpacked MV3 extension in isolated Playwright Chromium profiles. It intercepts fictional Sakai pages, native forms, academic tools, files and copyright endpoints. The Node suite evaluates conservative state/classification helpers and verifies packaged assets, provenance, permissions and first-party syntax. It does not log into LUMS. Added tests retain this architecture.

## Findings and disposition

| Area | Classification | Evidence, cause and correction |
|---|---|---|
| History write after Clear | **Confirmed defect** | A held storage `set` callback can finish after another tab's `clear()` returns and recreate the removed entry. The generation check ran before the asynchronous write. Mutations now acquire one origin-wide Web Lock before any asynchronous work. Startup migration, concurrent opens, eviction and clear share that lock. Clear completes only after earlier writes and its own removals finish. Errors reject instead of falsely reporting success. |
| Account isolation | **Confirmed defect** | Two fictional students opening the same resource use the same baseline key. New keys incorporate a SHA-256 account scope obtained exclusively from Sakai's authenticated current-session entity. Missing identity disables history. Old unscoped entries are removed, never attributed to the current student. Account changes invalidate preview caches; old preview completions cannot mark a new account. |
| Duplicate PDF initialization | **Confirmed defect** | Two data messages received while dynamic import is pending both create a loading task. The reader now reserves initialization synchronously before import and accepts one payload only. |
| PDF continuations after close | **Confirmed defect** | Controlled import/page/render completions can create a task or update state after pagehide. Every awaited boundary now checks lifecycle state and task ownership. An idempotent release cancels rendering, destroys the loading task, clears resize/deadline work and releases the canvas backing store. |
| PDF duplicate terminal handling | **Confirmed defect** | Parse rejection/password/teardown paths can retain a failed task or destroy it repeatedly. A single error/closed terminal state releases it exactly once. New tests cover password rejection, missing canvas and a stalled page render; page renders have a 20-second deadline. |
| Office late viewer ownership | **Confirmed defect** | Closing during `PptxViewer.open()` then receiving its result destroys that viewer, but the baseline retains it for another destruction on repeated pagehide. Late results are now destroyed before assigning ownership; owned viewers are nulled before destruction. Word, Excel, archive, import and slide continuations check terminal state. |
| Stalled response cancellation | **Confirmed defect** | A controlled response body can remain pending after abort, and stream read rejection previously released its lock without cancellation. Abort now cancels the body; failures cancel and release it. Actual fetch abort was already supported; this correction covers the independent stream boundary. |
| Whole-list rescans from unrelated widgets | **Reproduced only under stress** | With 1,000 added rows, baseline unrelated-widget mutation/RAF median was 327.7 ms, p95 399.8 ms. A deterministic content-world probe counted 26 document-wide queries for five clock updates. Scoped observer filtering eliminates these queries without changing table adaptation. The portal observer also avoids refreshes for unrelated shell children. |
| Stale parent iframe messages | **Not reproduced** for an old reader modifying a newer reader | Baseline already validates source window, extension origin and random token. New integration tests preserve that boundary; the parent also requires an active, nonterminal state. Reader errors/timeouts release frame/buffer ownership and provide retry. |
| Copyright replay | **Not reproduced** | Acceptance is called only by the explicit Yes button. Retry creates a fresh read-only preview, never stores or reuses an acceptance URL. Existing notice, decline, protected-PDF/Office and hostile-link tests remain required. |
| Redirect/permission bypass | **Not reproduced** | Same-origin reads use manual/error redirect modes. Redirect handling requests only the native same-origin require endpoint. Acceptance URLs are bound to the original resource. HTTP 401/403 remain permission failures. No submission-related request is retried. |
| Archive expansion / active Office content | **Not reproduced** | Existing traversal, encryption, entry/expanded-byte limits and stream validation remain. Office CSP blocks network/forms/child frames; external media, alternate HTML chunks, navigation and formula evaluation remain disabled. Bundled provenance hashes are unchanged. |
| Unbounded preview cache / repeated reader leak | **Potential risk**, no monotonic leak established | Existing cache stays at six entries / 24 MB. Stress samples use forced GC and DOM/listener counters, not just heap snapshots at arbitrary moments. Results and the distinction between warmup, detached worlds and a leak are in the verification report. |
| Basic LMS startup / OFF restoration | **Not reproduced** | Existing and new fixture checks cover `/`, `/portal`, `/portal/`, `//portal`, courses, gateway, same-origin tools, refresh and Back/Forward. Native content is not gated on fonts, graphics or preview imports. No startup redesign was made. |
| Baseline glow / immediate resize assertions | **Potential risk in test timing** | The first full baseline browser run had two failures under simultaneous stress: glow sampling and a synchronous bounding-box assertion immediately after viewport resize. The glow check passed alone. Post-fix resize coverage passed. These are recorded as baseline warnings, not silently reclassified as fixed product defects. |

Regression source: `tests/lifecycle.cjs`, `tests/reliability.cjs`, `tests/stress.cjs`, with neighboring existing reader, status, resource-variant, startup, academic and fallback suites. Regression tests were committed separately before fixes. The expanded deterministic suite reports 5/21 passes against the preserved baseline and 21/21 after fixes. Some new safety assertions have no baseline API equivalent; the report distinguishes those from runtime reproductions.

## Account identity contract

Sakai's [SessionEntityProvider at tag 25.2](https://github.com/sakaiproject/sakai/blob/25.2/entitybroker/core-providers/src/java/org/sakaiproject/entitybroker/providers/SessionEntityProvider.java) defines the read-only `current` action, returning an `EntitySession` with its session ID hidden. [EntitySession](https://github.com/sakaiproject/sakai/blob/25.2/entitybroker/core-providers/src/java/org/sakaiproject/entitybroker/providers/model/EntitySession.java) obtains `userId` from the authenticated server session. The implementation accepts that direct entity's nonempty `userId` only. It does not use user names, course IDs, URL account hints, cookies, or fabricated identities.

The lookup is same-origin, no-store, redirect-denying and bounded to three seconds. Concurrent badge lookups share an in-flight request; identity is rechecked on subsequent batches/opens and focus/restoration. It never blocks rendering native LMS content. Unsupported custom response envelopes safely disable history. Deployment-specific compatibility needs manual verification. Hashes remain pseudonymous and locally guessable, not encryption; no raw ID is persisted.

## Security and dependency review

Only the `storage` permission and original LMS match patterns remain. No analytics, telemetry, remote renderer, academic upload or external font/script was added. Document reads remain GET-only; the native explicit copyright GET is the sole existing acknowledgement path. Messages validate source, origin, type and token. Parent-owned transferred buffers, frame references and blob URLs are released on close/error/timeout. PDF evaluation/XFA/annotations remain disabled. Office restrictions and archive limits were not relaxed.

`npm audit` on the locked **development** graph reports zero vulnerabilities. This does not audit the committed browser bundles. A separate temporary npm graph using exact runtime package versions was checked against registry advisory metadata; it is evidence of package advisories, not an exact reconstruction of every minified bundle's dependency graph.

The public [PDF.js GHSA-hq66-cqwq-w95j / CVE-2026-16633 advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) lists 5.6.205 in the affected range. Its stated exploit conditions involve scripting enabled and absence of a restrictive script CSP. Aether uses core canvas rendering, does not instantiate PDFScriptingManager/the viewer scripting subsystem, disables annotations, and already has MV3 script restrictions. This patch adds an explicit PDF document policy allowing only packaged scripts and workers, with no inline JavaScript, JavaScript eval, external connections, forms or child frames. This follows the advisory's CSP workaround. Passing tests do not mean the bundled version is patched or that every PDF.js vulnerability is excluded. A reviewed 6.x upgrade remains follow-up work, not a silent change in this patch.

The reconstructed runtime graph also reports a moderate [uuid buffer-bounds advisory GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq) through ExcelJS. Aether supplies neither caller-controlled UUID output buffers nor UUID operations; its entry point is bounded XLSX loading and read-only stored values. Exact reachability through the upstream browser bundle has not been formally proven. No high-severity Office exploit was reproduced; keep this dependency risk visible for upstream review rather than downgrade ExcelJS or replace a large renderer without format validation.

Manually copied sanitized diagnostics were deferred to avoid feature expansion. No reporting service was added.
