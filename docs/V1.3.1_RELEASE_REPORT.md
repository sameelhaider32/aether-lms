## Memory and performance procedure

`npm run test:stress` opens/closes 100 PDF previews, navigates/zooms/fits during ten cycles, opens each of PPTX/DOCX/XLSX ten times, alternates two loading PDFs 30 times, adds/removes 1,000 resource rows, updates an unrelated widget on 30 frames, and performs 20 course/tool transitions. It records post-GC JS heap, documents, DOM nodes, event listeners, main-thread task duration, preview latency, requests and uncaught page errors. It also asserts the final preview is removed and requests are GET-only.

Baseline: PDF-open median 733 ms / p95 1,434 ms; 1,000-row readiness 5,307 ms; unrelated-mutation median 327.7 ms / p95 399.8 ms. The heap warmed from 2.41 MB to 3.59 MB by cycle 20, then 3.81 MB at cycle 100. DOM nodes were 686 at cycle 20 and 690 at cycle 100; listeners remained 138. Thirty Office previews ended at 3.83 MB / 689 nodes / 138 listeners. After 20 navigations, heap was 2.49 MB. No uncaught page errors were recorded.

These observations do not establish a monotonically growing leak. Repeated forced GC and stable document/listener counts help distinguish cache/JIT warmup from retained-reader growth. DOM counters include document worlds, and the primary-page heap metric does not comprehensively measure every worker or process allocation. This is not a zero-leak claim. Raw baseline and post-fix JSON evidence is retained with the release deliverables.

Post-fix stress: PDF-open median 391 ms / p95 1,488 ms; 1,000-row readiness 1,937 ms; unrelated-mutation median 16.6 ms / p95 17.0 ms. At PDF cycle 20, heap was 3.50 MB / 687 nodes / 143 listeners; cycle 100 was 3.70 MB / 688 nodes / 143 listeners. After 20 navigations heap was 2.59 MB / 687 nodes / 130 listeners. The five additional standing listeners implement session restoration/invalidation; they did not accumulate per preview. No uncaught page errors were recorded. Request count increased from 30 to 497 because account identity is now revalidated; those additional requests are same-origin, read-only session lookups. The small p95 latency increase is within this uncontrolled host sample's variability and is reported rather than hidden; repeated preview/list behavior otherwise improved.

The initial packaged Windows smoke passed 74/74, including the two added security checks. Rejected-payload recovery, tool-transition and external-dialog preservation extend the final packaged suite to 77 checks. An independent WSL Ubuntu run on Node 24.10.0 / Chromium 156 passed the then-current 116 browser, 21 startup/portal, 5 fallback and 41 unit/lifecycle checks. The exact final-head Windows/Linux CI and packaged results are recorded in the accompanying final evidence. Do not treat an uncompleted remote check as a pass.

## Release limitations

- Live authenticated Sakai behavior and the deployed session API need manual validation.
- Complex/legacy/encrypted Office files, unsupported PDF/canvas limits, unavailable codecs and site CSP restrictions retain Open original; rendering is not pixel-identical Office editing.
- History is unavailable without an authoritative direct current-session response or Web Locks. Unscoped old history is intentionally discarded; appearance and ordering preferences remain.
- Published runtime advisories and deferred upgrades are described in `V1.3.1_AUDIT.md`; a zero-vulnerability npm development audit does not clear committed runtime libraries.
- Optional diagnostics were deferred. No telemetry, academic writes, main merge or automatic release publication was added.
