# Spatial Home (1.7)

The initial Home Overview is a shared full-viewport composition in both themes. The old framed hero and permanent navigation gutter are replaced by centered existing typography, a viewport-adapted particle field, a small original orbital lattice and floating controls. The course dock follows in the natural page flow, then Mission Control and original Home widgets. Nothing is fabricated and native widgets/iframes are not moved or cloned.

## Integration

- `home-layout.js` commits `ae-spatial-home` only after the workspace, header, actual Sakai menu, replacement menu control and cleanup are ready. The actual sidebar receives drawer styling in place; its links, handlers, expand controls and dynamic structure remain native. Attributes/classes are journaled and restored on OFF, route changes, detached shells and disposal. An initial failure leaves native navigation available. The drawer has a close control, click-away, Escape, focus containment/return and an inert background; pending focus work is cancelled on close/disposal. Native header controls retain their nodes and handlers. Native All Sites/modal launchers and header actions release the drawer focus state before their original handler opens another surface. The native menu button is hidden only while the Home replacement is active.
- `content.js` uses visible Home context plus Overview/Home tool context, rejecting gateway, course and individual Home tool pages. It hands enable/render/history events to the layout controller without patching Sakai history. Mutation observation handles delayed and replaced shells; no polling or duplicate controller instances. Pointer movement adds bounded focal parallax only when motion is enabled.
- `home.css` owns Home geometry behind the active class. It changes no font families or palette identity, and places no transforms/filters on native modal or iframe ancestors. It uses the actual header height, responsive grid/text sizes and native page/drawer/dock scrolling. Main/sidebar geometry restores by removing the scope. The original pinned cards retain source links, saved order and existing animation support; overflow stays inside their horizontal dock. Original Home wrappers receive a clear heading and responsive spacing in place.
- `scene.js` adds a Home composition parameter to the existing single WebGL renderer, with matching placement in the existing 2D first frame/fallback/context-loss path. Courses use their old placement. Existing particle budgets, resolution limits, hidden/offscreen suspension and disposal remain. The small lattice is inline SVG/CSS, not a second graphics engine or context. Theme tokens color it; existing grayscale rules cover particle canvases.
- `download-ui.js` puts its existing Home entry with the floating controls, retaining the existing download controller. Mission Control, academic/resource adapters, chart code, previews, font bundles and theme storage are reused.

## Focused verification

`npm run test:home` uses the real extension folder with fictional, intercepted GET-only LMS pages. It checks 1920, 1440, 1024, 775 and 390 px widths, full-width/no-border/centered geometry, text/focal/action separation and no horizontal page overflow; visually records desktop/mobile in both themes; tests original navigation-node identity, focus loop/return, Escape/click-away and native header controls; checks actual course targets, course/deadline actions, theme persistence, motion/reduced motion, OFF/reload/ON and attribute restoration; checks native course/Home-tool layouts, native hamburger behavior, native DOM/history transitions, Back, delayed shell replacement, many pinned courses and keyboard dock access; and confirms WebGL-disabled Canvas rendering.

`npm run test:theme` additionally covers live theme updates, frame/PDF chrome, resource controls, academic views and native forms. Its audit ignores hidden/inert drawer content when checking visible monochrome colors. No full local stress/regression suite was run for this change.

## Boundaries

No new dependencies, permissions, backend operations, academic requests or persistent settings. Red is deferred. Authored documents and external viewers remain independent. Automated screenshots contain fictional data; live authenticated LUMS DOM variations remain unverified. If Sakai presents an unsupported shell, native navigation stays available instead of guessing navigation targets.
