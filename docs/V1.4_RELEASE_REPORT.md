# Aether LMS v1.4.0 verification and security report

Date: 24 October 2026. Baseline: merged v1.3.1
`f8bbeb6e7d76430e4a0f9151022d07ab90105cb1`. Feature branch:
`feature/v1.4-smart-downloader`. No authenticated LUMS session was used. All data
and documents in automated artifacts are fictional intercepted fixtures.

## Implementation and findings

The download manager uses one normalized tree and inherited selection engine for
individual files, arbitrary folder descendants, recursive course roots and mixed
available-course selections. Separate native Sakai selection remains intact.
Only expansion/review/discovery fetch metadata; only export reads file bytes.
The local basket survives manager exploration/closure within the same page,
expires after 30 minutes idle, and clears on session change, OFF or departure.

| Finding | Classification and disposition |
|---|---|
| Cloned resource buttons lose element-bound handlers | **Confirmed during implementation.** A native `cloneNode(true)` copy retains the button but drops `onclick`. Failing Chromium reproduction: 0/1; after delegated per-frame handling: 1/1. Full suites retain the regression. Original native controls are unchanged. |
| Own button insertion causes another whole-record scan | **Confirmed during profiling.** A controlled download-control insertion dispatched one extra records update; it now dispatches zero. List/preview observers ignore batches consisting solely of owned download controls, while native rows and attachment roots retain observation. |
| One-level shortcut discloses unloaded children and continues queued reads after Cancel | **Confirmed in shortcut-specific tests.** Expansion now advances a unique frontier and awaits each folder's result; an aborted result stops the queue. Both failing browser reproductions pass after the correction. |
| Unenumerated ancestors treated as incomplete when selecting one known file | **Corrected model risk.** Explicit file intentions do not require recursive ancestor API support. Deterministic and browser fallback tests verify this independent workflow. |
| Cancellation between picker/import/stream/finalization stages | **Hardened and regression tested.** One task owns abort/destination/session state. A late initialized destination is aborted, duplicate starts are ignored, and account changes stop finalization. |
| Unknown/duplicate/truncated collection schemas | **Potential deployment risk, fail visibly.** Strict root/child validation marks failures or partial results, with retry and explicit partial review. No empty-folder assumption on failure. |
| Cross-account stale baskets/history associations | **Not reproduced after controls.** Basket metadata is memory-only and cleared on identity change; no basket storage/migration exists. v1.3.1 history isolation is preserved. |
| Previous-account progress retains filenames after reset | **Confirmed during final review.** The tree cleared but progress still referenced failed nodes/current filename. A failing deterministic regression now passes: reset clears progress and replaces discovery state, and HTTP 401 also clears session-bound data. No migration or persistent basket exists. |
| Reader/manager resource retention | **No accumulating leak established in measured runs.** Forced-GC samples and limits are reported below. This is not a zero-leak claim. |
| LUMS course API/role variability | **Unverified deployment compatibility.** Available-site API results and native navigation are distinct from an enrollment-completeness claim. Hidden/restricted records are conservatively excluded; native controls remain the fallback. |

## Automated coverage

Baseline Windows suite before edits: 21 existing unit/security, 21 deterministic
lifecycle, 21 startup/portal, 121 main browser and 5 fallback checks all passed.

Added Node checks: 9 selection, 14 discovery/network, 12 controller and 6 archive
checks. They cover inherited selection/exclusions, overlaps, malformed hierarchy,
1,000 children, server-clamped pagination, duplicate requests, explicit-file
fallback, cancellation/deadlines/truncation, session changes, picker activation
ordering, delayed initialization, partial decisions, byte limits and ZIP paths.

Added actual-MV3 browser checks cover lazy discovery, recursive/nested selections,
mixed courses, failed enumeration retry, exact-resource copyright acceptance and
skip, hostile HTML, active cancellation/OFF, account changes, cloned controls,
keyboard/focus, Back/Forward, same-origin frames and responsive widths
360/390/775/1024/1440/1920. Native filesystem streaming is independently extracted.
The workflow runs these on Windows/Linux, then runs existing packaged smoke plus
downloader checks against the built extension. Exact-head CI status and logs are
provided with the review PR and release verification artifact; a scheduled check
is not considered a passing result.

## Performance and memory

Local environment: Windows x64, Node 22.20.0, Playwright 1.64.1, Chromium
156.0.8078.4, reduced motion, 1440 × 1000. Measurements are fictional fixtures on
an uncontrolled host, with forced main-page GC. Browser/process memory, file
system caches and native buffers are not comprehensively represented by JS heap.

An initial downloader profile of 100 manager open/close cycles measured median
59 ms / p95 78 ms. Loading a 1,000-file tree took 351 ms; search-input samples were
26–170 ms. Later delegated controls reduced per-record listeners; final raw
profiles accompany the release. Metadata is intentionally cached in page memory.
No tree virtualization was introduced: the measured 1,000-entry workload remained
usable without a second rendering architecture. Very large trees on older
hardware remain a limitation within the 10,000-node safety budget.

The later 100-cycle profile measured 53 ms median / 59 ms p95 open time and a
394 ms 1,000-file discovery/render. Closed cycles 10/50/100 each had 710 DOM nodes
and 140 listeners after forced GC; heap was 2.98/3.08/3.19 MB (decimal). The
populated tree deliberately adds roughly 9,000 visible DOM nodes; closing it
releases those nodes while retaining metadata. Search samples ranged 22–166 ms.
Screenshot/layout refinements are rechecked in the final suite; these timings are
measurements of the described run, not fixed performance promises.

A serial paired large-Resources comparison after the observer correction used
three fresh profiles per version: v1.3.1 845/836/653 ms, v1.4 747/1114/753 ms for
1,000 inserted rows. Medians were 836 vs 753 ms; the 1,114 ms outlier is retained.
The broader preview run measured median/p95 227/392 ms on v1.3.1 vs 244/420 ms on
the initial v1.4 integration, and unrelated-mutation median/p95 remained 16.7/17 ms.
The latter v1.4 run overlapped another stress profile, so this is not a controlled
latency speedup/regression claim. Both had 499 read-only requests and no uncaught
errors. PDF cycle 20→100 listeners remained 143→143 (baseline) and 153→153 (v1.4),
with no surviving PDF workers or reader frames at post-close samples. Fixed
downloader integration listeners do not grow per preview; no course/file scan or
ZIP import is introduced on idle startup.

The archive test generates 128 MiB without retaining a complete input file. With
64 KiB source chunks, measured producer lead was 786,364 bytes in the Node sink
run, and 851,890 bytes in the real native browser filesystem run. Output starts
before the source completes. The native stream wrote a 134,218,022-byte archive;
Python verified CRC and the 134,217,728-byte entry. These tests demonstrate
incremental backpressure, not total browser memory equal to the producer lead.
The Blob mode intentionally retains its bounded archive, and rejects output over
64 MiB even with unknown or dishonest size metadata. Direct output is capped at
2 GiB; >4 GiB and multi-volume exports are not supported in this release.

The existing stress workload repeats 100 PDF previews, 30 Office previews, 30
loading alternations, 1,000 Resources rows and 20 navigations. Separate exact
v1.3.1 and v1.4 profiles, main-thread/frame timing, listener/node samples and
request counts accompany the release. Worker/frame counts return to zero after
reader closure in the measured samples. Host load affects timing; no unsupported
“zero memory leaks” or universal speed improvement claim is made.

## Security and privacy review

- Extension permission remains only `storage`, with the same LMS host scope.
- No analytics, external ZIP/conversion service, remote executable code, academic
  writes, broad filesystem permission or persistent basket/history was added.
- Metadata and files use authenticated same-origin GET. Content URL identity,
  redirects, notice acceptance and origin restrictions are validated. Copyright
  acceptance is per-resource and explicit; manual retry does not replay it.
  Downloader action buttons require trusted user events, including copyright
  consent; a synthetic page-script click is regression-tested as inert.
- Session checks reuse the authoritative hashed v1.3.1 identity, at reasonable
  task boundaries and active-only intervals. Missing identity blocks export.
- No archive contents are executed. Filesystem errors abort output; source errors
  omit the entry from the central directory and require partial-output consent.
- Zip paths protect traversal, separators, reserved names, case collisions and
  long Unicode components. Response filenames cannot change the selected mapping.
- zip.js 2.24.0 was checked against the current npm registry and separately
  reconstructed dependency audit (0 advisories at audit time). Its core bundle,
  BSD license, npm integrity and SHA-256 provenance are committed. The development
  lockfile audit also reports 0 advisories. These npm checks do not audit every
  committed runtime library.
- Existing PDF/Office versions remain unchanged; the v1.3.1 advisory assessment
  and restrictive reader policies still apply. No claim is made that unchanged
  vendored runtimes have become patched or advisory-free.

## Known limitations and manual validation

1. Validate authenticated LUMS folder/site APIs and student/TA/instructor behavior.
   Upstream depth and field contracts are inspected; LUMS deployment is unverified.
   No promise of every enrolled course, hidden file or archived host is made.
2. Exercise Chrome's actual OS save dialog, overwrite confirmation, cancellation,
   disk-full conditions and extracted archives on Windows/Linux. The picker exists
   in the actual content world and respects headless cancellation; native stream
   writing is tested through a temporary fictional browser file, not an automated
   selection in the OS dialog.
3. A full navigation/restart cannot carry a running export. UI closure confirms
   cancellation; native beforeunload warnings depend on browser policy. OFF
   cancels immediately. Chrome can leave a newly picked destination empty after
   abort. Aether does not delete a pre-existing user destination for cleanup.
4. The 2 GiB ceiling is a safeguard, not a throughput guarantee on every machine.
   ZIP64 records are verified below conventional limits; larger archives are not
   advertised. STORE avoids entry buffering but does not reduce file sizes.
5. Filters search discovered metadata only. Unsupported URL variants, external
   links, unavailable metadata and permission-limited records retain native
   fallback. API size/version estimates may change before the later GET.
6. A partial archive may contain unindexed bytes from an interrupted entry; its
   central directory and successful entries are independently verified. No failed
   file is represented as an empty successful entry.
7. Timing and GC variation are transient measurements. Older Chrome versions and
   assistive-technology combinations need manual coverage beyond Chromium 156.

No publishing, automatic merge, university submission/upload/deletion or live
student-data capture is part of verification.
