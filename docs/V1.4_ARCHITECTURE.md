# v1.4 resource export architecture and compatibility

Baseline: merged v1.3.1, `f8bbeb6e7d76430e4a0f9151022d07ab90105cb1`.
Branch: `feature/v1.4-smart-downloader`. Baseline Windows suite: 21 unit,
21 lifecycle, 21 startup/portal, 121 browser, 5 fallback checks passed.

## Feasibility evidence

No authenticated LUMS session was used. Deployment capabilities remain unverified.
The existing preview uses `/direct/content/resources/group/SITE/FOLDER.json?depth=1`.
Upstream [ContentEntityProvider](https://github.com/sakaiproject/sakai/blob/master/content/content-tool/tool/src/java/org/sakaiproject/content/entityproviders/ContentEntityProvider.java)
defaults to depth 1, supports integer depth or `all`, and checks each child's read
permission. We deliberately request one level at a time, serially. Its
`/direct/content/site/SITE.json` action returns a different, presentation-oriented
ContentItem schema; it is not used as an interchangeable recursive tree response.
EntityContent supplies resourceId, name, type, size, url, hidden, modified and
resourceChildren. Restricted children can be omitted by the server: completeness
means the accessible API listing, never every resource held by Sakai.

Upstream [SiteEntityProvider](https://github.com/sakaiproject/sakai/blob/master/entitybroker/tool/src/main/java/org/sakaiproject/entitybroker/providers/SiteEntityProvider.java)
supports `select=access`, `_start`, `_limit`; servers clamp page size. Advance by
the actual number returned until an empty page, detect repeated pages and enforce
a discovery budget. These are available sites, not a claim of all enrollments.
Native `/portal/site/ID` navigation and verified `/group/ID/` resource references
supply fallback roots. Pinned courses are not used as an enrollment list.
Unknown schemas, mismatched roots, invalid children and explicit truncation mark
discovery incomplete. Verified visible file entries still work independently.

The [Zambeel+ reference](https://github.com/Danish-H/zambeel-plus/blob/main/scripts/lms.js)
was inspected only for behavior. Its visible-link collection, whole-file buffers
and JSZip Blob generation are not copied. First-party implementation remains MIT.

## Export constraints

Locally bundled zip.js 2.24.0 (BSD-3-Clause), STORE entries, one stream at a time,
no workers/codecs, no parallel entry buffering. File System Access is detected
and the picker is invoked directly from the final user click, after review.
No filesystem permission is added. Unsupported/blocked pickers offer an explicit
64 MiB bounded Blob fallback; output bytes are checked regardless of metadata.
The release imposes a 2 GiB direct-stream ceiling, 10,000 nodes and depth 128.
ZIP64 records are tested on small archives; >4 GiB exports are not advertised.

Metadata and selection intentions live only in the current page's memory, expire
after 30 minutes, and are cleared on account change, logout, OFF or page departure.
No file contents are stored in extension storage. A running export cannot survive
page navigation; beforeunload warns when the browser permits it. UI closure asks
before cancellation. OFF cancels immediately and restores native operation.
