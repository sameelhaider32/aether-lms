# v1.4 resource export architecture and compatibility

Baseline: merged v1.3.1, `f8bbeb6e7d76430e4a0f9151022d07ab90105cb1`.
Branch: `feature/v1.4-smart-downloader`. Baseline Windows suite: 21 unit,
21 lifecycle, 21 startup/portal, 121 browser, 5 fallback checks passed.

## Feasibility evidence

No authenticated LUMS session was used. Deployment capabilities remain unverified.
The existing preview uses `/direct/content/resources/group/SITE/FOLDER.json?depth=1`.
Upstream [ContentEntityProvider](https://github.com/sakaiproject/sakai/blob/master/content/content-tool/tool/src/java/org/sakaiproject/content/entityproviders/ContentEntityProvider.java)
defaults to depth 1, supports integer depth or `all`, and checks each child's read
permission. We deliberately request one level at a time, serially. Its
`/direct/content/site/SITE.json` action returns a different, presentation-oriented
ContentItem schema; it is not used as an interchangeable recursive tree response.
EntityContent supplies resourceId, name, type, size, url, hidden, modified and
resourceChildren. Restricted children can be omitted by the server: completeness
means the accessible API listing, never every resource held by Sakai.

Upstream [SiteEntityProvider](https://github.com/sakaiproject/sakai/blob/master/entitybroker/tool/src/main/java/org/sakaiproject/entitybroker/providers/SiteEntityProvider.java)
supports `select=access`, `_start`, `_limit`; servers clamp page size. Advance by
the actual number returned until an empty page, detect repeated pages and enforce
a discovery budget. These are available sites, not a claim of all enrollments.
Native `/portal/site/ID` navigation and verified `/group/ID/` resource references
supply fallback roots. Pinned courses are not used as an enrollment list.
Unknown schemas, mismatched roots, invalid children and explicit truncation mark
discovery incomplete. Verified visible file entries still work independently.

The [Zambeel+ reference](https://github.com/Danish-H/zambeel-plus/blob/main/scripts/lms.js)
was inspected only for behavior. Its visible-link collection, whole-file buffers
and JSZip Blob generation are not copied. First-party implementation remains MIT.

## Export constraints

Locally bundled zip.js 2.24.0 (BSD-3-Clause), STORE entries, one stream at a time,
no workers/codecs, no parallel entry buffering. File System Access is detected
and the picker is invoked directly from the final user click, after review.
No filesystem permission is added. Unsupported/blocked pickers offer an explicit
64 MiB bounded Blob fallback; output bytes are checked regardless of metadata.
The release imposes a 2 GiB direct-stream ceiling, 10,000 nodes and depth 128.
ZIP64 records are tested on small archives; >4 GiB exports are not advertised.

Metadata and selection intentions live only in the current page's memory, expire
after 30 minutes, and are cleared on account change, logout, OFF or page departure.
No file contents are stored in extension storage. A running export cannot survive
page navigation; beforeunload warns when the browser permits it. UI closure asks
before cancellation. OFF cancels immediately and restores native operation.

## Selection rules

`Tree.nodes` holds metadata keyed by a validated decoded `/group/SITE/...`
reference. Parentage must be a direct path descendant of the verified parent;
cross-site children, cycles, duplicate/conflicting identities and malformed
references cannot silently establish a complete collection. An API URL must map
back to exactly that reference on the intended LMS origin, without credentials,
query or fragment. Non-content/signed-query URL variants remain unsupported and
retain the native link fallback. No arbitrary URL fetch facility is exposed.

`Tree.rules` stores true/false intentions, resolved at the nearest ancestor.
Selecting an unloaded folder stores one positive rule; later descendants inherit
it. Unchecking a child stores a negative exception. Selecting/unselecting a
parent clears rules below it, so selecting a parent after individual children is
predictable. Separate courses share this same model. A stable resource appears
only once in the final snapshot, even if both parent and child were selected.
Checkboxes expose native checked/indeterminate state plus `aria-checked`; unknown
discovery is labeled separately. Counts before review say “at least”; size
estimates separately identify unknown lengths. Complete accessible listings can
be empty; unavailable folders are never represented as empty.

Search/type filters reveal matching **loaded** metadata and never mutate rules.
No server-wide search completeness is claimed. Explicit visible-file selections
do not require enumerating unrelated ancestors. Recursive intentions trigger
serial breadth-first discovery of their selected subtrees before any bytes are
read. Excluded branches are not fetched. Partial discovery requires an explicit
checkbox confirmation; later file failures require another keep/discard decision.

## Lifecycle and cancellation

Controller stages are browsing → discovering → ready → choosing → downloading
→ finalizing → completed, with copyright/partial decision states and failed or
cancelled terminal states. A single current task excludes duplicate starts and
owns its abort controller, active-session check and archive writer. The save
picker is invoked synchronously from Start, before the first await. Missing or
blocked APIs offer the separate small-export button; picker cancellation retains
the selection and sends no content request. Session validation follows picking.

Metadata requests are capped at 4 MiB / 20 seconds. File streams have a 30-second
idle deadline and 30-minute per-file deadline, response-length verification where
Content-Length is usable, and actual-byte ceilings. GET redirects are not followed
externally; only the existing bounded native notice procedure is used. HTML
login/notice/error responses are not silently saved as non-HTML files. HTML files
can be exported as inert bytes; none of the archive's contents is executed.

The ZIP writer uses 64 KiB configured chunks, level 0 (STORE), no web workers,
`bufferedWrite:false` and sequential awaited `add()` calls. The browser/network
and library have their own bounded queues; “64 KiB” is not a claim that total
heap use is exactly one chunk. Backpressure and independent ZIP extraction are
tested. zip.js removes failed source entries from its central directory, allowing
a confirmed partial archive without empty placeholders. Interrupted local entry
bytes may remain unindexed; keeping partial output is explicit. A destination
write/size failure aborts the entire output rather than attempting recovery on a
broken sink. Direct writes are committed only when finalization closes the
filesystem stream. Cancellation aborts it; a newly picked file can remain empty,
and no pre-existing user destination is deleted for cleanup.

Archive components normalize Unicode, replace separators/control/Windows-invalid
characters, protect reserved names and dot segments, and limit UTF-8 length.
Stable-ID order determines case-insensitive collision suffixes. Names come from
metadata/visible entries, never a response-header filename override. A map retains
the exact resource-to-archive-path association.

## Browser/platform evidence

[Chrome's save API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)
requires a secure context and user activation. The unpacked MV3 test calls the
real picker from the isolated content world with activation and observes native
headless cancellation. A separate native FileSystemWritableFileStream test writes
128 MiB through the real browser API, downloads that fictional test artifact and
has Python independently verify its ZIP contents/CRC. Temporary origin-private
test files are removed; the product does not use OPFS staging. Selecting a real
OS destination and overwrite/cancel behavior remain a manual save-dialog check.
The ZIP options follow the [zip.js writer contract](https://gildas-lormeau.github.io/zip.js/api/interfaces/ZipWriterConstructorOptions.html).

Only the core minified module and BSD license/provenance are shipped. Workers,
codecs, the npm graph and Zambeel+ code are not copied into the extension. Existing
PDF/Office runtime versions and extension permissions remain unchanged.
